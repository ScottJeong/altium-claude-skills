# 기하 넷 구성 — Altium 과 개수를 맞추는 법

`altium_monkey` 의 넷리스트 컴파일러(`AltiumDesign.to_netlist`)가 **회로도에 따라 죽는다.**

```
ValueError: compiled schematic pin terminal has no component body evidence:
            physical:0:logical:0:Sheet1.SchDoc:SB?:2
```

원인은 심볼 쪽이다 — `SOLDERBRIDGE` 처럼 **사각형 본체 없이 폴리라인·아크로만**
그려진 심볼, 멀티파트 커넥터 등에서 걸린다. 지정자를 채워도 실패 지점만 옮겨간다.

그래서 **배선 좌표로 직접 넷을 만든다.** `scripts/net_erc.py` 가 그것이다.

## 처음에 틀렸던 것 — 배선만 보면 안 된다

1차 구현은 "배선 선분 위에 있는 핀" 만 넷에 넣었다. 결과:

```
내 도구 : 105 넷
Altium  : 182 넷      ← 77개 차이
```

빠진 것이 셋이었다.

| 빠뜨린 것 | 왜 |
|---|---|
| **핀-핀 직결** | 두 부품 핀이 배선 없이 맞닿아 있으면 배선 검사에 안 걸린다 |
| **핀-전원포트 직결** | 전원포트가 핀 위에 바로 놓인 경우 |
| **hidden 핀** | Altium 이 **이름으로 자동 연결**한다. 배선이 애초에 없다 |

게다가 이 핀들을 **넷 그래프에서 통째로 뺐다.** 그래서 "단일핀 넷 0건" 같은
결론이 나왔는데, 실제로는 검사 대상에서 빠진 것뿐이었다.

## 고친 방법

union-find 를 **선분과 단자 전부**에 대해 돌린다.

1. 배선 선분끼리: 끝점이 닿거나 한쪽 끝이 다른 선분 위면 union
2. **모든 단자**(핀·전원포트·넷라벨)를 노드로 넣는다. 배선에 안 닿아도 **버리지 않는다**
3. 단자가 어떤 선분 위에 있으면 그 선분과 union
4. **좌표가 같은 단자끼리 union** ← 핀-핀 / 핀-포트 직결이 여기서 잡힌다
5. 전원포트·넷라벨 **이름이 같으면** union
6. **hidden 핀은 핀 이름으로** 같은 이름 넷에 union

고친 뒤 **182 넷 — Altium 과 일치**했다.

## 좌표 단위

`altium_monkey` 는 여기서도 비대칭이다.

| 대상 | 단위 |
|---|---|
| `get_pin_hotspot(핀designator)` | **mil** |
| 배선 `points`, 전원포트·넷라벨 `location` | **10mil** |

섞으면 전부 미결선으로 보인다. **한쪽을 ×10 해서 맞춘다.**
매직넘버로 박지 말고 두 좌표계의 최대값 비율로 배율을 구하면 안전하다.

그리고 `get_pin_hotspot` 은 **핀 designator 문자열**을 받는다. 핀 객체를 넘기면
전부 예외가 나고, 폴백으로 핀의 상대좌표를 쓰게 되어 결과가 통째로 틀어진다.

## 허용 오차

`TOL = 5 mil`. Altium 격자가 보통 100mil 이라 넉넉하다.
너무 키우면 서로 다른 넷이 붙고, 0 이면 부동소수 오차로 놓친다.

## 이 방법의 한계

기하만 본다. 못 보는 것:

- **버스·버스엔트리**
- **시트 심볼 / 계층 설계** (여러 시트)
- **off-sheet 커넥터, 포트**
- 컴파일 마스크, 배리언트

단일 시트 평면 설계면 문제없다. **계층 설계면 Altium 컴파일 쪽을 써야 한다.**

## 검산은 항상 개수로

넷 개수를 Altium `DM_NetCount` 와 **반드시 비교**한다.
다르면 기하 구성에 구멍이 있는 것이고, 그 상태의 검사 결과는 믿으면 안 된다.
