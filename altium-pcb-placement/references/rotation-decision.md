# 주요 IC 회전 결정

## 왜 계산이 되는가

QFN/QFP/LQFP 는 핀번호가 변을 결정한다. 그러니 "이 IC 를 어느 쪽으로 돌릴까" 는
취향이 아니라 **어느 신호 무리가 어느 변에서 나오는가** 하나로 정해진다.

절차는 셋뿐이다.

1. 핀번호 → 변 매핑을 **확인**한다 (추정 금지)
2. 신호를 무리로 묶고, 각 무리의 상대 부품이 어느 방향에 있어야 하는지 정한다
3. 회전 4안을 돌려 무리 방향이 맞는 것을 고른다

## 1. 핀1 위치와 진행 방향은 반드시 확인한다

`--start` 와 `--dir` 이 틀리면 **결과 전체가 뒤집힌다.** 표준이 대개 맞지만
(핀1 = 좌상, 반시계) 그걸 근거로 삼지 않는다.

확인처, 강한 순서대로:

| 출처 | 무엇이 보이나 |
|---|---|
| **본드 다이어그램** | 핀1 삼각 마커, 각 변의 핀번호 범위와 신호명 전부 |
| 패키지 도면 / 데이터시트 핀아웃 | 같은 정보. 회전 텍스트가 누락될 수 있다 |
| PINOUT 엑셀 | 번호·신호명은 있으나 **변 정보는 없다.** 단독으로는 부족 |

본드 도면은 텍스트가 벡터 아웃라인이라 `get_text()` 로 안 나온다.
**고배율(2.5~3x)로 렌더해서 눈으로 읽는다.**

```python
import pymupdf
d = pymupdf.open(path)
pix = d[0].get_pixmap(matrix=pymupdf.Matrix(2.6, 2.6))
pix.save('bond.png')
```

읽을 것: 핀1 마커 위치 · 각 변의 시작/끝 핀번호 · 변당 핀 수.
**변당 핀 수는 (총핀수 / 4) 가 아닐 수 있다.** OPEN/NC 가 섞인 패키지가 있다.

## 2. 신호를 무리로 묶는다

`connectivity_matrix.py --ref <IC>` 출력의 "핀별 상대" 열을 쓴다.
**상대 부품이 같은 핀들이 한 무리**다. 신호 이름으로 묶지 말고 상대로 묶는다 —
배치를 정하는 건 이름이 아니라 "누구한테 가는가" 다.

무리마다 원하는 방향을 정한다. 이건 §0 에서 캔 사용자 제약에서 나온다.
예: 커넥터가 좌변이면 그 커넥터로 가는 무리는 `W`.

## 3. 4안 비교

```
python scripts/pin_side_map.py --pins-per-side 17 --start left --dir ccw \
  --group "MII=1-12,61-68" --group "BUS=14-22,25,32,33,39,40" \
  --group "ANALOG=44-57" --want "MII=NE" --want "BUS=W"
```

방향은 무리 핀들이 속한 변의 단위벡터 평균이다. 그래서 **한 무리가 두 변에 걸치면
대각(NE/NW/SE/SW)이 나온다.** 대각이 나오면 그 코너 대각선 위치에 상대를 놓는 게 최적이다.

## 예 — 64핀 QFN

패키지 도면에서 확인: 핀1 = 좌상, 반시계, 변당 16핀.

```
P1~P16   좌     P17~P32  하     P33~P48  우     P49~P64  상
```

무리 (`connectivity_matrix.py` 의 「핀별 상대」 열에서 뽑는다):

| 무리 | 핀 | 상대 |
|---|---|---|
| BUS_A | 1-10, 55-64 | 옆에 붙일 IC |
| BUS_B | 18-30 | 보드 변의 커넥터 |
| ANALOG | 36-50 | (자기 디커플링) |

```
python scripts/pin_side_map.py --pins-per-side 16 --start left --dir ccw   --group "BUS_A=1-10,55-64" --group "BUS_B=18-30" --group "ANALOG=36-50"   --want "BUS_A=NE" --want "BUS_B=W"
```

결과:

| 회전(CCW) | BUS_A | BUS_B | ANALOG |
|---|---|---|---|
| 0° | 좌상 NW | 하 S | 우 E |
| 90° | 좌하 SW | 우 E | 상 N |
| 180° | 우하 SE | 상 N | 좌 W |
| **270°** | **우상 NE** | **좌 W** | 하 S |

커넥터가 좌변이라는 제약이 있으면 `BUS_B=W`, 상대 IC 를 우상에 두고 싶으면 `BUS_A=NE`.
**270° 하나만 둘 다 만족한다.**

**BUS_A 가 두 변에 걸쳐 코너(NE)로 나온 것이 핵심이다.** 코너로 몰린 무리는
그 대각 위치에 상대를 놓으면 교차가 0 이 된다. 한 변에만 있는 무리보다 배치가 쉽다.

## 커넥터는 다른 규칙으로 정한다 — 핀 매핑이 아니라 개구부 방향

IC 회전은 핀→변 매핑에서 나오지만 **커넥터 회전은 그 방법으로 안 나온다.**
커넥터에 필요한 건 「어느 무리가 어느 변인가」가 아니라 **「개구부가 어디를 보는가」** 다.

> **보드 변에 붙는 커넥터는 「패드 bbox 대비 실크가 더 튀어나온 쪽」이 개구부다.
> 그 방향이 보드 바깥을 향하도록 회전을 정한다.**

케이블이 들어가는 쪽에는 패드가 없고 하우징만 있다. 그래서 패드 bbox 와 실크 bbox 를
따로 재서 차이를 보면 방향이 나온다. 데이터시트를 안 봐도 된다.

```
python scripts/connector_facing.py <SchDoc> --libs <라이브러리폴더>
```

실측 예 (rot 0 기준, 패드 대비 실크 돌출 아래/위):

| 부품 | 아래 | 위 | 개구부 |
|---|---|---|---|
| DC 잭 | **6.70** | 0.10 | −Y |
| USB-C | **2.21** | −2.41 | −Y |
| RJ45 | **4.90** | 1.04 | −Y |
| 96핀 R/A | **9.06** | 0.30 | −Y |

넷 다 rot 0 에서 아래를 본다. 그러면 **상변에 놓을 커넥터는 rot 180**, 좌변은 rot 270,
우변은 rot 90 이다. 변만 정하고 회전을 안 건드리면 **개구부가 보드 안쪽을 향한다.**

실측 사례 — 커넥터 3개를 상변에 `rot 0` 으로 놓았다. 좌변의
R/A 커넥터는 rot 270 을 줘서 맞았는데, 상변 셋은 회전을 안 줘서 전부 반대였다.
**bbox 는 180° 회전으로 안 변하므로 겹침 검사·외곽 검사에 안 걸린다.** 사용자가 화면을
보고 지적했다. 배치 검증 항목에 「커넥터 개구부 방향」을 따로 넣어야 하는 이유다.

## 함정

- **패키지 핀번호 ≠ 다이 패드 번호.** 본드 도면은 둘 다 나오니 어느 쪽인지 본다.
  회로도 심볼이 쓰는 번호(= 패키지 핀)로 계산해야 한다
- **소켓을 쓰면 소켓 풋프린트의 A1 방향**이 칩 핀1 과 같은지 확인한다. 소켓은
  별도 부품이고 A1 마킹이 따로 있다
- 무리가 세 변 이상에 흩어지면 회전으로 못 푼다. 그 IC 는 어디에 둬도 교차가 난다 —
  회전보다 **상대 부품 배치를 나누는 게** 답일 수 있다
