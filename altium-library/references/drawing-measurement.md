# 벤더 2D 도면에서 치수 뜨기

풋프린트의 근거는 결국 도면이다. 그런데 벤더 도면은 그냥 읽히지 않는다.

## 왜 텍스트 추출이 안 되나

Hirose 등 벤더의 2D 도면 PDF 는 **문자가 텍스트가 아니라 벡터 아웃라인**이다.
`page.get_text()` 를 부르면 워터마크 조각 하나 정도만 나온다.

```
--- text spans in hole-pattern view ---
  y=  268.1 x=  726.7 horiz 'ENCE'      # "HRS DRAWING FOR REFERENCE" 워터마크
```

치수 숫자는 전부 path 다. 그래서 두 가지 길밖에 없다:

1. 해당 영역을 고해상도로 렌더해서 **눈으로 읽는다** — 숫자를 읽는 데는 이게 맞다
2. **도형 좌표를 직접 잰다** — 위치·간격은 이쪽이 정확하다

## 눈대중은 하지 마라

렌더한 이미지에서 픽셀로 거리를 어림하는 건 **하지 마라.**
한 세션에서 세 번 시도했고 세 번 다 틀렸다. 특히:

- 뷰가 **break(`~`) 로 잘려 있으면** 그 방향의 축척이 안 맞는다.
  브레이크를 가로지르는 거리는 절대 재면 안 된다 (도면상 88.9mm 가 40mm 로 나온다)
- 선 굵기 때문에 경계가 1~2px 씩 밀린다
- 렌더 스케일 → 표시 스케일 이중 변환에서 오차가 쌓인다

숫자는 렌더해서 읽고, **거리는 벡터로 잰다.** 역할을 나눈다.

## 스케일 역산

도면의 절대 좌표는 의미가 없다. 대신 **이미 아는 치수 하나**로 pt/mm 을 역산한다.
핀 격자 피치가 제일 안전하다 (2.54mm 등, 여러 번 반복돼서 평균 낼 수 있다).

```python
row_y = [...]                                   # 행 중심선 y (pt)
gaps  = [row_y[i+1] - row_y[i] for i in range(len(row_y)-1)]
pt_per_mm = sum(gaps) / len(gaps) / 2.54
```

**반드시 검산한다.** 도면에 적힌 *다른* 값으로 확인:

```
pin hole  O = 0.794 mm   (도면 0.8)     <- 1% 이내. 스케일 OK
mount hole O = 2.787 mm   (도면 2.8)
```

안 맞으면 스케일이 틀렸거나 다른 뷰를 재고 있는 것이다. 여기서 멈추고 원인을 찾는다.

## 원이 곡선이 아닐 수 있다

`page.get_drawings()` 의 item 종류를 먼저 세어본다:

```python
Counter({'l': 9604, 'qu': 303})     # 'c'(곡선)가 하나도 없다
```

이 도면의 원은 **폴리라인 근사**다. `c` 만 찾으면 하나도 못 잡는다.
그래서 판정 기준을 이렇게 바꾼다:

- 경로의 bbox 가 **가로세로 거의 같고**(차이 12% 이내)
- 크기가 합리적 범위 안이고
- 세그먼트가 6개 이상(폴리라인 근사)

그 다음 지름별로 히스토그램을 내면 핀홀 무리와 마운팅홀 무리가 자연히 갈린다.

## 선 굵기가 실체와 보조선을 가른다

이게 결정적이다. 같은 y 에 실선이 여러 개 있어도 의미가 다르다:

```
y=340.79  x 110.00..126.70  lw=0.425   <- 치수 보조선 (도면 왼쪽 치수란까지 뻗음)
y=340.79  x 129.60..146.60  lw=0.992   <- 부품 외곽
```

**굵은 것만 골라야 외곽이 나온다.** 안 나누면 치수선을 부품 외곽으로 착각한다.
굵기 값은 도면마다 다르니 히스토그램을 내서 두 무리로 갈린다는 것만 확인하면 된다.

보조선은 대개 도면 가장자리(치수란)까지 뻗으므로 x 범위로도 걸러진다.

## 어떤 뷰를 봐야 하나

| 찾는 것 | 뷰 |
|---|---|
| 패드/홀 위치·지름, 마운팅홀, 권장 보드엣지 | `RECOMMENDED PC BOARD HOLE PATTERN` |
| 하우징 외곽, 핀 격자 대비 바디 위치 | 평면도(plan view) |
| 행 이름(a/b/c)·접점 번호 방향 | 하면도/정면도 (번호가 여기에만 있는 경우가 많다) |
| 부품 높이 | 정면도(mating face view) |

**홀 패턴 뷰에는 접점 번호가 없는 경우가 흔하다.** 번호 방향은 다른 뷰에서 가져와야 하는데,
뷰가 여러 개 세로로 쌓여 있으면 투상 규칙으로 좌우를 확정할 수 없다.
이럴 때는 **추측하지 말고 사용자에게 실물/짝 커넥터로 확인받는다.** 미러 방향이 갈리는 지점이다.

## 치수의 기준선을 의심하라

숫자가 있다고 그게 내가 생각한 두 점 사이 거리라는 보장이 없다.

실제 사례: 도면의 `12.7` 을 하우징 깊이로 읽었는데, 실측해보니
**하우징 뒷면 → 첫 핀행** 거리였다. 하우징 깊이는 `12.7 - 1.5 = 11.2` 였다.

판정법: 실측값과 도면 숫자를 **여러 조합으로 맞춰본다.** 전부 아귀가 맞는 해석이 정답이다.

```
하우징 근접 엣지  A행에서 -1.447mm   <- 도면 (1.5)
하우징 원단 엣지  A행에서 -12.65mm   <- 도면 12.7
깊이 = 12.65 - 1.447 = 11.2mm       <- 12.7 은 깊이가 아니었다
```

전장(A)과 바디길이(B)가 따로 있으면 그 차이는 대개 **양끝 돌출부(마운팅 귀)** 다.
`(94.00 - 88.00) / 2 = 3.00mm` 처럼 딱 떨어지면 확신해도 된다.

## 스크립트

`scripts/measure_drawing.py` 가 위 절차를 구현했다.

```
python scripts/measure_drawing.py <도면.pdf> \
    --clip 0.55 0.03 0.95 0.36 \
    --pitch 2.54 \
    --render out.png
```

- `--clip` 은 페이지 비율(x0 y0 x1 y1). 먼저 `--render` 로 전체를 뽑아 어느 영역인지 정한다
- `--pitch` 는 스케일 역산에 쓸 알려진 간격 (mm)
- `--lines` 를 주면 선분도 굵기별로 덤프한다 (외곽 추출용)
